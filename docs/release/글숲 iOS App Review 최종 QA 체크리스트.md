# 글숲 iOS App Review 최종 QA 체크리스트

## 1. 목적
Apple App Review 반려 사유(Guideline 1.2, Guideline 4)를 기준으로 실제 기기에서
**재제출 전 반드시 확인해야 할 항목**을 최종 점검한다.

## 2. 사용 방법

- `- [ ]` : 아직 확인 전
- `- [x]` : 확인 완료
- 실제 제출 전에 각 섹션의 "최종 판단" 항목까지 함께 체크한다
- 이 문서에서 `Codex`가 체크한 항목은 `코드/설정 검토` 또는 `자동 검증 통과` 기준이다
- `실기기`, `실서버`, `운영자(admin)`, `화면 녹화` 확인이 필요한 항목은 그대로 미체크 상태로 남긴다

## 3. Codex 확인 결과 (2026-04-15)

- **자동 검증 통과**
  - `npm run lint`
  - `npm run typecheck`
  - `npm run release:ios:verify:config`
  - `../glsoop`에서 `npx playwright test tests/e2e/safety-api.spec.js --project=desktop-chrome`
- **코드/설정으로 확인한 범위**
  - 공개 UGC 진입 전 `PublicUgcNoticeGate` 노출 및 체크 후 진입 구조
  - 약관/개인정보/가이드라인/지원 링크 UI 존재
  - 신고/차단 UI 및 API 연결
  - 차단 시 blocked user store 갱신과 Home/Search/Author 목록 필터링
  - 계정 센터의 차단 목록/차단 해제 화면 존재
  - iOS 설정의 `supportsTablet=true`, `requireFullScreen=true`
- **실응답/서버 검증으로 확인한 범위**
  - `https://www.glsoop.com/html/terms.html`, `privacy.html`, `community-guidelines.html`, `/support` 모두 `200`
  - 위 문서/지원 페이지 모두 viewport meta 존재
  - production runtime config에서 `report_enabled=true`, `block_enabled=true`, `moderation_sla_hours=24`
  - server safety API 테스트에서 신고 접수, admin safety queue 조회, 신고 resolve, 차단 후 숨김, block-source report 생성 통과
  - admin route에서 `GET /api/admin/safety/reports`, `POST /api/admin/safety/reports/:id/resolve`, `DELETE /api/admin/posts/:id`, `DELETE /api/admin/users/:id` 확인
  - `iPhone 13`, `iPad Air 11-inch (M3)` simulator boot 확인
- **iOS Simulator 실화면으로 확인한 범위**
  - `iPad Air 11-inch (M3)` Simulator Safari + Expo web에서 공개 UGC 정책 게이트 전체 카드가 한 화면에 표시되고, 텍스트/버튼 겹침이나 잘림 없이 보이는지 캡처로 확인
  - `iPhone 16e` Simulator Safari + Expo web에서 공개 UGC 정책 게이트 문구, 문서 링크, 지원 카드가 작은 화면에서도 읽히는지 캡처로 확인
  - `iPad Air 11-inch (M3)` Simulator에서 Expo Go 실행 및 최근 프로젝트(`glsoop-mobile`) 표시까지 확인
- **이번 세션에서 모바일 웹 E2E 참고만 함**
  - Expo web server는 수동 기동으로 우회 가능했지만, 기존 `e2e/home.spec.ts`, `e2e/account-center-blocked-users.spec.ts`는 현재 UGC notice gate / 최신 문구와 기대값이 어긋난 흔적이 있어 release 근거로 직접 사용하지 않았다
  - 따라서 모바일 앱 쪽은 `코드 검토 + 외부 링크 실응답 + server safety API 실제 테스트`를 주 근거로 사용했다
  - 시뮬레이터 실화면 캡처는 `정책 게이트 노출/가독성`과 `iPad 첫 화면 레이아웃` 확인에는 도움이 됐지만, native iPad 스크롤/글쓰기/설정 사용성 전체를 대체하진 않으므로 관련 항목은 보수적으로 미체크 유지했다

## 10. iPad UI / 스크롤 / 레이아웃 QA

- [ ] iPad에서 앱이 정상 실행된다
